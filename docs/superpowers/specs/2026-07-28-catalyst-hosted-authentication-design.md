# Catalyst Hosted Authentication Recovery

## Goal

Replace the non-functional embedded Catalyst login flow on `ace.onslate.in` with Catalyst hosted authentication while preserving the branded ACE login shell, demo credentials, premium attribution, and post-login return to ACE.

## Root Cause

Catalyst Web SDK 4.6.2 generates same-origin `/accounts/...` iframe URLs. On the Slate custom domain, the sign-in page renders but its required `/accounts/p/70-50043872568/encryption/script` request is handled by Slate's SPA fallback and returns `text/html`. Email submission then stalls because the encryption helper is not JavaScript. Rewriting the iframe to `accounts.zohoportal.in` is invalid because the hosted page forbids framing through `frame-ancestors 'self'`.

## Design

- Mount Catalyst sign-in into a non-visible URL-discovery host.
- Observe the iframe URL generated by the official SDK so all project, portal, recovery, CSS and service-return parameters remain Catalyst-owned.
- Convert only the generated URL origin from the ACE origin to the configured Catalyst authentication origin.
- Remove the generated iframe and expose a normal same-tab `Continue to secure sign in` link.
- Keep the branded identity panel, demo credentials card, copy actions and premium Catalyst attribution unchanged.
- Show a bounded loading state until the hosted URL is available and the existing safe error state if URL discovery fails.
- Do not accept arbitrary redirect origins; only same-origin `/accounts/` URLs may be converted.

## Security

- No passwords, tokens or session material are handled by React.
- Navigation is restricted to `https://accounts.zohoportal.in` and a Catalyst-generated `/accounts/` path.
- The Catalyst return URL remains the existing `__catalyst/.../auth/signin-redirect` endpoint and returns to `/`.
- No Authentication whitelist, CORS, iFrame, backend, persona or dashboard configuration changes are required.

## Verification

- Unit tests cover strict URL conversion and rejection of unrelated URLs.
- Component tests prove the iframe is not displayed and the hosted link retains Catalyst query parameters.
- Existing auth, router and viewport regression suites pass.
- Production build passes.
- Live testing confirms the hosted page accepts the demo account and returns to the ACE workspace selector.
